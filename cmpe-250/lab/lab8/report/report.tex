\section*{Abstract}

The purpose of this exercise was to design a program written in Keil ARM-v6-M
Assembly using the Thumb 1 instruction set capable of performing addition
operations on numbers of arbitrary word length stored in memory. The ADCS
instruction was used to add successive word chunks of the number while
respecting the Carry flag. A basic TUI was implemented to get an n-word number
from a user; user input was case-insensitive, and leading zeroes were optional.
The program was tested with various inputs to ensure overflow, carry, and
inputs of different lengths worked as expeceted. The exercise was successful,
as all test inputs produced the correct outputs.

\section*{Procedure}

A Keil MDK-ARM project was created. Provided libraries were added to Source
Group 1 of the project. Subroutines including \texttt{GetStringSB},
\texttt{PutStringSB}, and \texttt{PutNumHex} were included from previously
written code. A subroutine \texttt{HexToBin} was adopted from the main loop
of a previous exercise. A subroutine AddIntMultiU was implemented using the
\texttt{ADCS} instruction. Multi-word numbers were stored in memory, with the
least signifigant byte stored at the highest memory address. Upon loading the
word into registers, the byte order of the registers were reversed, such that
the low end of the register contained the least signifigant byte. Two numbers
were loaded from memory and summed, one word at a time. The least signifigant
word was loaded first. After computing the sum of each word, the resultant word
was stored to an offset from a storage address.

A subroutine \texttt{GetHexIntMulti} was written to get numbers of N word
length from a user. It moved the stack pointer and established a buffer in
stack space. Text was read from a user, converted to binary, and then stored to
memory (not the stack buffer). If the user entered an invalid hexadecimal
string, the subroutine exited with the C flag set.

A subroutine \texttt{PutHexIntMulti} was written to print a binary number of N
word length to UART in ASCII-encoded hexadecimal. Each word of the number was
individually loaded and sent to a previous exercise's \texttt{PutNumHex}
subroutine to print the character.

A main program was written to dislay a basic user interface. It requested two 4
word (128 bit, 32 character) inputs from the user in hexadecimal, performed
basic validation, and printed the some or displayed whether the sum overflowed.

The program was translated and built. Target options were modified to allow the
debugger to work with the flashed chip. The program was flashed to the KL05Z.
The windows program PuTTY was configured to communicate with the chip. The
program was tested with a variety of inputs, including partially empty prompts,
prompts with extra characters, capital and lowercase characters, small numbers,
big numbers, and overflowing numbers.

\section*{Conclusion}

The objective of this exercise was to design subroutines and algorithms capable
of processing and performing arithmetic operations on number of arbitrary
length. Subroutines iterated over the number in memory to operate on just parts
of it at a time. The addition subroutine made use of the \texttt{ADCS}
instruction to preserve carry from previous operations. Due to time
constraints, poor subroutine design was used in the \texttt{GetHexIntMulti} and
\texttt{ReverseRegister} operations. In a future revisit to this project, both
subroutines could be altered to reduce size and improve execution speed; the
latter subroutine may not be required at all. In the future, operating on
arbitrary-length data will be necessary to create large, expandable projects.
The skills gained in this exercise will be applicable outside of mere
arithmetic.
