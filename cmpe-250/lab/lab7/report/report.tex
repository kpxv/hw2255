\section*{Abstract}

The purpose of this exercise was to desgin a circular queue using the NXP
Freedom KL05Z board. The queue was described with a record in memory, and
implemented inside of a buffer in memory. Subroutines took the record address
as arguments and performed I/O on the buffer. A TUI menu was created to control
the queue; string and character I/O subroutines were reused from previous
exercises. The TUI allowed users to enqueue, dequeue, print queue, print queue
status, and get help. The program was translated, compiled, and flashed to the
KL05Z. It was tested with various inputs at various queue capacities. All
outputs were printed correctly. The queue properly handled dequeue from empty,
enqueue to full, and displaying queue contents in decimal and hexadecimal
representations. The exercise was successful.

\section*{Procedure}

A Keil MDK-ARM project was created. Provided libraries were added to Source
Group 1 of the project. A subroutine \texttt{GetStringSB} was written using
a previously written subroutine to recieve a single character. The subroutine
stored a string from user input to a location in memory. It took as input R0,
the address of the memory at which to store the string; and R1, the total
allowable size of the string. If a backspace character was received, the memory
pointer was decremented. If a return character was recieved, a NUL terminator
was appended to the string and the subroutine exited. If a control character
was recieved, it was ignored. If the string size was one less byte than the
maximum, all inputs except return and backspace were ignored. Otherwise, the
input was appended to the string and the string pointer was incremented.

A subroutine \texttt{PutStringSB} was written using a previously written
subroutine to transmit a single character. The subroutine printed all
characters until either the buffer size was reached or a NUL terminator was
encountered.

A subroutine \texttt{PutNumU} was written using a previously written subroutine
to perform unsigned division. The subroutine took input R0 as the number to
transmit. It iteratively divided R0 and pushed the result to stack. It then
iteratively popped bytes from the stack, converted them to ASCII characters,
and transmitted them.

A main program was written to display a basic user interface. It requested a
one character input from the user and executed a different subroutine based on
the input. If input was a \texttt{g} or \texttt{G}, it requested a string from
the user using \texttt{GetStringSB}. If input was \texttt{p} or \texttt{P}, it
printed the string using \texttt{PutStringSB}. If input was \texttt{l} or
\texttt{L}, it printed the length of the string using \texttt{PutNumU}. If the
input was \texttt{i} or \texttt{I}, it set the operative string to a NUL
character.

The program was translated and built. Target options were modified to allow the
debugger to work with the flashed chip. The program was flashed to the KL05Z.
The windows program PuTTY was configured to communicate with the chip. The
program was tested with a variety of inputs, including control characters,
return, backspace, and strings of max buffer length.

\section*{Conclusion}

The objective of this exercise was to design safe algorithms for string I/O, as
well as to design a subroutine to convert an unsigned binary number into a
decimal ASCII number. Subroutines used a set maximum string size to ensure
no overflow could occur, regardless of input. In the future, safe string I/O
should be used in any serious project to prevent exploitation or accidental
breakages.
